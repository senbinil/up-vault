# RFC 0005: up-vault API

- **Status:** Draft
- **Date:** 2026-10-05
- **Depends on:** RFC 0002, RFC 0003, RFC 0004

## 1. Summary

This RFC defines the minimum HTTP API required by the up-vault MVP.

## 2. Endpoints

### Create Document

```http
POST /documents
```

Uploads and indexes a document.

### List Documents

```http
GET /documents
```

Returns indexed documents.

### Delete Document

```http
DELETE /documents/{document_id}
```

Deletes a document and its associated chunks.

### Query

```http
POST /query
```

Asks a question against the indexed knowledge base.

## 3. Create Document

### Request

```http
Content-Type: multipart/form-data
```

The request contains a document file.

### Response

```json
{
  "id": "uuid",
  "filename": "notes.md",
  "status": "indexed"
}
```

## 4. List Documents

### Response

```json
{
  "documents": [
    {
      "id": "uuid",
      "filename": "notes.md",
      "created_at": "2026-10-05T12:00:00Z"
    }
  ]
}
```

## 5. Delete Document

```http
DELETE /documents/{document_id}
```

Successful deletion returns:

```http
204 No Content
```

## 6. Query

### Request

```json
{
  "question": "What database are we using?"
}
```

### Response

```json
{
  "answer": "The project uses PostgreSQL.",
  "sources": [
    {
      "document_id": "uuid",
      "filename": "architecture.md",
      "chunk_index": 3
    }
  ]
}
```

## 7. Error Responses

Errors should use a consistent format:

```json
{
  "error": {
    "code": "DOCUMENT_NOT_FOUND",
    "message": "Document was not found."
  }
}
```

Common errors include:

- `INVALID_DOCUMENT`
- `UNSUPPORTED_FILE_TYPE`
- `DOCUMENT_NOT_FOUND`
- `INGESTION_FAILED`
- `RETRIEVAL_FAILED`
- `LLM_ERROR`

## 8. API Design Principles

- Keep endpoints minimal.
- Use predictable HTTP status codes.
- Validate requests at the API boundary.
- Keep application logic outside route handlers.
- Return source information with RAG responses.

## 9. Authentication

Authentication is out of scope for the local MVP.

Authentication should be added before exposing the application publicly.
